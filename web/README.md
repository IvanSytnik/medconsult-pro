# MedConsult Turkey – web

Next.js (App Router, TypeScript, Tailwind CSS) site with Payload CMS 3 embedded. All copy, prices, photos, team,
videos and the order of page sections are edited in the admin at `/admin` in four languages (DE, RU, UK, EN).

## Development

```bash
cp .env.example .env         # DATABASE_URL and PAYLOAD_SECRET are required
npm install
npm run seed                 # fill an empty database with the site content and create the owner account
npm run dev                  # site on http://localhost:3000, admin on /admin
npm run build
npm run lint
```

Locally Payload syncs the database schema automatically. After changing collections, globals or blocks:

```bash
npm run generate:types       # src/payload-types.ts
npm run migrate:create       # new file in src/migrations, commit it
```

## Structure

- `src/payload.config.ts` – Payload config: Postgres, Vercel Blob, localisation (German default, fallback to German).
- `src/payload/` – collections (pages, services, treatments, clinics, team, videos, media, users), globals
  (site settings, legal) and page blocks (one per section type, each with an anchor and a hidden flag).
- `src/app/(frontend)/[locale]/[[...slug]]` – every CMS page; `home` is `/`, other slugs become `/<slug>`.
  `impressum` and `privacy` render the legal global.
- `src/components/blocks/` – one renderer per block type.
- `src/app/(payload)/` – admin and REST/GraphQL API generated by Payload.
- `src/seed/` – idempotent seed: the original copy (`data/*.json`) plus the figures, prices, team and media that
  used to be hardcoded. `SEED_FORCE=1` resets seeded documents to the original content.
- `messages/{de,ru,uk,en}.json` – only interface strings the CMS does not manage (form labels, language names).
- `src/app/api/submit` – contact form handler (validation, Telegram, Resend e-mail, rate limit).

Pages are statically generated; saving anything in the admin revalidates the site.

## Deploy

Vercel project with Root Directory `web`. The build (`scripts/migrate-on-vercel.mjs`) applies pending migrations and
seeds an empty database before `next build`. On a fresh database the first account created on `/admin` becomes the owner.
See `.env.example` for the variables.
